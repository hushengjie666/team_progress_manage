# 修复 macOS 菜单栏与应用内倒计时不同步

## 目标与使用场景
在 macOS 上从系统菜单栏或「开始工作」页面操作计时后，两处应持续显示同一计时会话。当前反馈是一处已经倒数，另一处仍显示 `25:00`。

## 本次范围
- 在当前远端 `main` 基线上从应用内和 macOS 菜单栏的已有入口复现问题，核对开始、暂停、继续、短休息和计时结束时的状态传递。切换任务通过应用内的现有入口验证。
- 让两处共用同一计时会话的阶段、运行状态与剩余时间依据。主窗口隐藏时菜单栏继续显示当前会话，窗口重新打开时按当前会话即时恢复显示。
- 沿用已有的专注、短休息、长休息、阶段准备及结算规则。

## 业务规则与异常边界
- 开始、暂停、继续或切换阶段后，两处在一个刷新周期内显示一致。连续倒数时，因刷新对齐产生的剩余时间差最多一秒。暂停或准备态显示一致的剩余时间和可用动作。
- 计时结束后进入同一个下一阶段。重复同步、快速操作和窗口恢复均按同一会话处理，只结算一次，番茄数和工作会话记录正确。

## 验收标准与测试计划
- macOS 原生验收覆盖两处分别发起开始、暂停和继续，从计时中切换短休息，以及隐藏窗口后继续计时与重新打开窗口。记录阶段和余时对照。
- 验证切换任务、专注完成和休息完成后的阶段衔接与记录数量。用自动化覆盖计时状态同步、过期更新和重复结算的回归。
- 按项目要求提供桌面和窄屏浏览器的计时业务回归、原生 macOS 菜单与应用页面的实际验证，以及当前提交的 CI 结果。
