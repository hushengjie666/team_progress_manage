# 任务完成视觉庆祝动效与多巴胺反馈体验

## 目标与使用场景
目前在「开始工作（专注）」页面点击左侧今日任务卡片的「完成」、中间「当下清单」的「完成任务」，以及在「我的任务」页面点击「完成任务」后，仅出现极短暂的徽章底色微闪或普通 toast 提示，感官反馈平淡、缺乏完成任务的爽感与仪式感。

本次需求在保持 TimeManage 温和克制的森林绿/纸感设计语言前提下，为任务完成操作打造高质感、流畅且不打扰交互的**纯视觉庆祝动效**（不播放音效），带来即时的正向成就感与多巴胺激励，并在“今日任务全部清零”时提供升级版里程碑庆祝效果。

## 实施依赖
- `#27`（`AD-007` 优化开始工作页左侧今日任务面板宽度与布局）的 AutoDev 任务 PR 合入项目主分支后再开工，以确保本需求直接基于新版左侧面板样式叠加完成动效，避免文件冲突。

## 本次范围
1. **统一覆盖三处完成入口（策略 1A）**
   - 「开始工作」页左侧「今日任务」卡片的「完成」按钮；
   - 「开始工作」页中间「当下清单」面板的「完成任务」按钮；
   - 「我的任务」工作台任务卡片的「完成任务」按钮。
2. **纯视觉多巴胺庆祝体系（策略 2B：纯视觉、不播放任何音效）**
   - **触发点微粒爆发 + 光环波纹**：任务确认完成瞬间，从触发按钮所在的屏幕坐标（键盘触发时取按钮中心，定位不可用时优雅回退到视口安全位置）爆发一束高质感彩色纸屑/几何微粒（采用与应用协调的森林绿、薄荷青、暖琥珀金、珊瑚橘等柔和饱和色，具重力、初速度扩散、轻旋转与空气阻力缓出）并叠加柔和扩张光环波纹。
   - **卡片与按钮爽感微动效**：
     - 左侧「今日任务」卡片刚完成时，除保留并强化 `.completed-pill.just-completed` 的勾选弹跳与 `focus-completion` 动效外，卡片叠加一道柔和的高光扫过（shimmer/glow）与轻微弹性回弹（spring bounce）反馈。
     - 中间「当下清单」与「我的任务」完成时，配合触发点爆发微粒，使“点下完成 → 任务切换/归档”的过程清晰可感而非突兀消失。
   - **轻盈成就浮标（Celebration Banner / Pill）**：在视口上方合适位置短暂停留（约 1.2–1.6 秒后自动平滑淡出）一张不抢焦点、不遮挡关键操作的成就浮标，展示正向激励反馈与今日达成计数（例如 `✓ 任务完成 · 今日第 N 项`）。
   - **今日全部清零升级彩蛋**：当本次完成使今日计划中的全部可见今日任务均变为已完成（且今日至少有 1 项任务）时，自动升级为更盛大的**今日全部达成庆祝彩带/双侧微粒礼花**，成就浮标升级展示今日全清祝贺（例如 `今日任务全部达成！`）。
3. **非阻塞与连击衔接**
   - 庆祝动效覆盖层固定为 `pointer-events: none` 且不触发页面滚动条或布局重排；快速连续完成多个任务时，新一次触发能平滑叠加/接续播放并自动清理离场，绝不卡顿或阻挡后续点击。
4. **严格纯视觉与无障碍尊重**
   - 全程**不播放任何音效**（不调用 `AudioContext` 或系统提示音）。
   - 严格尊重系统 `prefers-reduced-motion: reduce`：减弱动效模式下不渲染粒子爆发、光环扩散、卡片弹跳或高光动画，仅保留清晰的静态完成态提示。

## 明确不做
- 不播放任何任务完成音效，也不新增完成音效开关或音量设置（用户明确选择 2B 纯视觉）。
- 不增加动效风格选择器、设置页开关或后端用户偏好字段。
- 不修改后端 API、任务状态流转、自动验收/人工验收权限判定、计时器停止逻辑或排序分组规则。
- 不为「提交验收」（人工验收项目进入 `pending_review`）、保存失败、历史已完成任务的页面刷新或切页重进播放庆祝特效。

## 业务规则与异常边界
- **仅真正确认完成才庆祝**：只有在后端/状态确认该任务最终状态变为 `completed` 时才触发庆祝动效；点击「提交验收」后进入 `pending_review` 状态时**不触发**粒子庆祝与成就浮标（避免误导用户以为已通过验收）。
- **失败与防重**：请求被拒绝、网络失败或任务本身已是 `completed` 时不触发庆祝动效；请求进行中按钮防重复提交行为保持不变。
- **不重播历史**：刷新页面、切换路由再回到「开始工作」或「我的任务」时，绝不因已有已完成任务而重播庆祝动画或触发全清彩蛋。
- **今日全清判定边界**：仅在本次完成动作使今日列表从“存在未完成项”跨入“今日任务全部完成”的瞬间触发一次全清升级庆祝；若完成的是未列入今日计划的任务，正常播放单次完成庆祝，不误触发今日全清彩蛋。
- **性能与清理**：动效结束后自动清理动画帧、定时器与临时节点，避免内存泄漏或持续占用 GPU/CPU；不引起横向滚动溢出，不影响番茄钟圆环 `.focus-orbit` / `.timer-face` 的几何稳定。

## 验收标准
1. **三处入口均生效**：
   - 在「开始工作」页点击左侧今日任务卡片「完成」按钮确认完成后，从该按钮位置爆发彩色微粒与光环波纹，卡片呈现高光/回弹与勾选完成动效，并弹出轻盈成就浮标。
   - 在「开始工作」页点击中间「当下清单」的「完成任务」按钮确认完成后，从按钮位置爆发微粒与光环，并弹出成就浮标（即使当前任务随即切换为下一项，视觉庆祝依然清晰完整）。
   - 在「我的任务」页点击任务卡片的「完成任务」按钮确认完成后，同样从按钮位置爆发微粒并弹出成就浮标。
2. **今日全清升级效果**：当今日任务仅剩最后 1 项未完成并将其完成时，触发明显升级的全清庆祝效果与全清祝贺提示；完成后自动退场，不残留遮罩。
3. **严格边界与纯视觉**：
   - 人工验收项目点击「提交验收」进入 `pending_review`、或接口返回错误时，不触发任何粒子庆祝或成就浮标。
   - 刷新页面、切页返回时，历史已完成任务不重播庆祝特效。
   - 确认任务完成过程完全静音，不触发音频播放。
   - 动效覆盖层具备 `pointer-events: none`，不阻挡连续点击其他按钮，也不导致页面或面板出现横向溢出；番茄钟倒计时圆环几何全程稳定。
4. **无障碍与减弱动效**：在 `prefers-reduced-motion: reduce` 环境下，点击完成不播放粒子爆发与卡片动效，`.completed-pill` 保持 `animation-name: none`，核心完成状态与功能正常。
5. **既有契约不回归**：保留 `focus-completion` 动画名、`.completed-pill`、`.just-completed` 生命周期与既有快捷完成、计时器稳定性、移动端布局等所有回归测试通过。

## 必要技术约束与方案
- 保持 `focus-quick-completion.spec.ts` 所依赖的核心契约：在普通动效模式下完成左侧卡片任务时，仍通过 `.completed-pill.just-completed` 触发名为 `focus-completion` 的 CSS 动画，动画结束后移除 `.just-completed`；在 `prefers-reduced-motion: reduce` 模式下不触发该动画。
- 动效实现保持轻量（优先使用原生 Canvas / CSS 动画与独立封装模块），不引入过重第三方动画引擎；遵守仓库健康审计（单份 TS/TSX 文件不超 500 行，单份 CSS 不超 1000 行且尽量简洁）。
- 桌面端优先调优，同时确保手机窄屏（如 `390×844`）下微粒边界安全、不产生横向滚动或遮挡核心按钮。
