# 优化开始工作页左侧今日任务面板宽度与布局

## 目标与使用场景
在「开始工作（专注）」页面中，当前桌面端左侧「今日任务」面板偏窄，滚动条紧贴卡片右边框，任务标题字号偏大且外框套白卡显得拥挤；同时已完成任务与待办/执行中任务视觉权重几乎一致，导致已完成项占满视线、正在做和待做的任务不够突出。

本次优化旨在让桌面端左侧「今日任务」面板更宽敞舒展、层级清晰、呼吸感更好，同时保持右侧「每日一句」、「当前工作」和番茄钟圆环的视觉平衡与几何稳定。

## 本次范围
1. **桌面端宽度与三栏比例重平衡（自适应比例）**
   - 在桌面视口（`> 1180px`）下拓宽左侧「今日任务」面板至更舒适的宽度区间（目标约 `380px–440px`，约占主布局宽度的 `32%–35%`，随视口平滑自适应），适度收敛中间「当前工作」区多余的左右留白。
   - 保障 `1280×820`、`1365×900`、`1440×900` 及更宽桌面屏下，左侧面板明显变宽且右侧番茄钟圆环与「每日一句」不被挤压变形或截断。
2. **面板头部与滚动区呼吸感优化**
   - 顶部标题栏结构更紧凑，在「今日任务」区域补充简洁的今日进度摘要（例如待办数与已完成数；空列表时不显示多余计数），保留保存状态提示与右上角 `+` 快捷新增按钮。
   - 任务列表滚动区域增加右侧缓冲留白并预留稳定滚动条槽位，避免出现纵向滚动条时紧贴任务卡片右边框。
3. **任务卡片排版与视觉层级重设计**
   - 调整任务标题字号（约 `14px–15px`）、行高、内外间距与柔和边框层次，减轻“重框套重框”的局促感；合理拉开项目分组与卡片之间的视觉节奏。
   - **执行中任务**：突出当前正在计时的任务（如柔和强调底色、左侧强调标识或清晰边框区分 + `执行中` 徽章），一眼可定位。
   - **待办任务**：统一底部元信息（`实际/预估 番茄 · 百分比`）与操作按钮排布；`开始` 保持主按钮样式，`完成` / `提交验收` 调整为带轻边框或柔和底色的次按钮，视觉规整且在桌面与手机窄屏下保持同一水平行。
   - **已完成任务（保留分组内 + 弱化紧凑）**：继续留在各自项目分组内不折叠隐藏，改为更低对比度的柔和底色、轻量字体与更紧凑的卡片高度，明显让位于未完成和执行中任务；保留 `已完成` 状态徽章及刚完成时的反馈动效。
   - **待验收任务**：保持清晰、柔和的 `待验收` 徽章样式，与待办和已完成区分开。
4. **响应式与无障碍体验保持**
   - 在 `≤ 1180px` 及手机窄屏（如 `390×844`）下保持上下堆叠排布自然、无横向溢出。
   - 保留按钮键盘 `Tab` 焦点顺序、清晰可见的 `solid` 焦点轮廓与空格键隔离行为。

## 明确不做
- 不增加左侧面板鼠标拖拽调宽交互及自定义宽度持久化。
- 不增加已完成任务的折叠/展开开关或额外筛选标签。
- 不修改后端接口、数据库结构、任务排序/项目分组规则及快捷完成/提交验收权限逻辑。
- 不修改番茄钟计时行为、倒计时圆环核心交互逻辑或「每日一句」业务功能。

## 业务规则与异常边界
- **空列表**：今日任务为空时正常展示空态提示文案，头部进度摘要不出现冗余或错位，右上角 `+` 按钮可用性规则不变。
- **超长文案**：超长项目名称与超长任务标题（含中英文及连续长串）正常折行，面板、卡片及标题均不出现水平溢出（`scrollWidth - clientWidth <= 1`）。
- **多项目与高完成率混合**：多个项目分组且存在较多已完成项时，纵向滚动顺畅、分组顺序在开始/切换任务后保持稳定，用户可快速分辨执行中与待办任务。
- **权限与保存中态**：无快捷完成权限的卡片隐藏完成按钮后底部仍对齐自然；保存中（`pending`）按钮禁用态清晰；已移出今日列表但仍在计时的任务行为不受影响。
- **减弱动态效果**：遵循 `prefers-reduced-motion: reduce`，禁用刚完成动效与非必要过渡。

## 验收标准
1. **桌面端宽度与平衡**：在 `1280×820`、`1365×900`、`1440×900` 桌面视口打开「开始工作」页，左侧「今日任务」面板实际宽度落在约 `380px–440px` 舒适区间；右侧 `.focus-orbit` 与 `.timer-face` 倒计时全程保持正圆、居中、无溢出与零抖动，「每日一句」与「当前工作」区显示完整自然。
2. **滚动与留白**：当任务列表超出容器高度出现纵向滚动条时，滚动条与卡片右边框之间留有清晰间距，无贴边压迫感，且面板与卡片无水平溢出。
3. **头部与状态层级**：面板顶部显示清晰的今日进度概览与 `+` 新增按钮；「执行中」「待办」「待验收」「已完成」四种卡片视觉区分明确，已完成卡片高度更紧凑、视觉权重明显低于待办/执行中卡片且保留在原项目分组中；待办卡片的 `开始` 与 `完成`/`提交验收` 按钮样式规整并在同一水平行。
4. **窄屏与无障碍**：在 `390×844` 手机视口下，面板、卡片与长标题无水平溢出，操作按钮同行可点；键盘 `Tab` 聚焦按钮时呈现清晰 `solid` 焦点轮廓；`prefers-reduced-motion: reduce` 下无完成动画。
5. **既有行为不回归**：开始/切换任务时项目分组顺序稳定，快捷完成与提交验收流程、会话关闭与持久化结果完全符合既有预期。

## 必要技术约束与方案
- 保留现有组件公开 props、关键 DOM 语义与测试依赖的选择器/文案（如 `.focus-todo-panel`、`.focus-todo-list`、`.focus-project-heading`、`.focus-todo-item`、`.completed-pill`、`.just-completed`、`article`、按钮可访问名称「开始」「完成」「提交验收」等）。
- 遵循项目健康规范：单份 CSS 文件保持简洁易维护（严禁超过 1000 行，建议控制在 500 行以内），TS/TSX 文件不超 500 行。
- 桌面端优先调优，同时保障既有窄屏/移动端响应式布局与测试通过。
