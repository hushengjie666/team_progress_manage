# 日常任务字段与每日自动加入今日任务机制

## 目标与使用场景
目前系统里的「重复规则（`repeatRule`）」仅在任务完成后克隆一条新任务丢进项目任务池，不会自动进入「今日任务」，且会在项目中不断累积同名历史任务副本。

本次需求引入正式的**「日常任务」**概念：用户可以在任务字段中将该任务标记为日常任务；开启后，系统每天都会自动将其加入「我的今日任务」。用户当天点击完成时，仅表示完成了**今天的这一次日常打卡**，次日（新的一天）该任务会自动重新以待办状态出现在今日任务中，除非用户手动删除该任务（或主动关闭其日常任务开关）。

## 本次范围
1. **任务字段与配置入口**
   - 在任务模型中新增「日常任务」开关字段，以及按用户本地日期（`YYYY-MM-DD`）记录的每日完成日期与当日移出状态（保持向后兼容，既有任务默认为非日常任务）。
   - 在以下入口提供清晰的「日常任务」开关，支持创建时设定及后续随时开启/关闭：
     - 项目详情内的「新建任务」弹窗；
     - 「开始工作」/「我的任务」中的快捷新增任务弹窗；
     - 任务详情编辑面板（排期/属性区域）。
   - 在「我的任务」、「开始工作」左侧今日任务及项目任务列表中，为日常任务展示清晰简洁的轻量 `日常` 标识（策略 2A：轻量实用版，不额外展示连续打卡天数统计）。
2. **每天自动加入「我的今日任务」**
   - **归属判定（策略 1A）**：属于当前用户可访问项目、未删除且非 `archived`/`split` 状态的日常任务，若主执行人或协作者包含当前账号，或未指定执行人且由当前账号创建/属于个人项目，则归属为当前用户的日常任务。
   - **自动纳入机制**：
     - 每天进入新日期（按用户本地日期 `YYYY-MM-DD`）首次打开应用、数据刷新同步或页面自然跨过本地 00:00 时，系统自动将属于当前用户的日常任务纳入当日「今日任务」（同步反映在「我的任务」今日清单与「开始工作」左侧今日任务），无需手动从活动清单添加。
     - 新建日常任务或将已有任务切换开启为日常任务时，若当天尚未在今日清单中，即时纳入当天「今日任务」。
   - **当日手动移出与永久停止的区别**：
     - 当天将日常任务从「今日任务」移回活动清单，仅使该任务在**今天**不再自动加回今日；**次日（新的本地日期）仍会自动加入今日任务**。
     - 只有用户**手动删除该任务**、归档该任务或主动**关闭「日常任务」开关**，才会永久停止每日自动加入。
3. **「只完成今天，明天自动重置」的完成语义（单任务按日打卡）**
   - **单任务实体**：日常任务始终保持为同一条任务记录，完成时不克隆新任务副本，也不触发旧版 `repeatRule` 的任务复制逻辑。
   - **直接完成今日打卡（策略 1A）**：在「开始工作」左侧今日任务、中间「当下清单」或「我的任务」点击完成日常任务时，**直接标记为今日已完成**（即使所在项目关闭了自动验收 `autoAcceptCompletedTasks === false`，日常任务也直接完成今日打卡，不卡在人工验收状态）。
   - **当天表现**：点击完成后，正常结束该任务当前运行中的番茄/工作会话并保留完整工作记录（不影响周专注趋势和历史工时统计）；在**当天**的「今日任务」与「开始工作」中显示为「已完成」并计入当日完成状态，不再出现在今日待办中，当天不可重复完成。
   - **次日自动重置**：跨入次日（新的本地日期）后，昨日完成状态自动翻篇，该任务在次日「今日任务」中自动恢复为未完成待办状态（当天可重新开始计时与点击完成），历史完成日期与过往会话记录完整保留。
4. **前后端持久化与多端同步**
   - Go 团队后端与前端本地/缓存状态均完整持久化日常任务标记、按日完成日期记录及当日移出记录，确保刷新页面、重新登录或跨设备同步后，当天的完成/移出状态与次日自动出现行为一致。

## 明确不做
- 不在卡片或详情页展示「连续打卡天数 / 累计完成次数」等习惯激励统计（用户确认采用轻量版 2A）。
- 不新增“仅工作日/自定义星期”的日常任务排期子规则（本次「日常任务」固定为每天自动加入）。
- 不改变普通一次性任务的既有生命周期、人工验收流程与旧版 `repeatRule` 对非日常任务的行为。
- 不破坏现有 MySQL `v0.1.2+` 数据库表结构与既有数据兼容性（优先利用现有关系存储与扩展 JSON 持久化机制，如确需 schema 变更须严格遵循项目迁移规范）。

## 业务规则与异常边界
- **本地时区跨天一致性**：日常任务的“今天”与“明天”严格按用户**本地日期（`YYYY-MM-DD`，与今日计划 `DailyPlan.date` 和 `localDateForTimestamp` 一致）**判定，后端记录今日完成日期时接收或遵循客户端本地日期，避免 UTC 时差导致北京时间凌晨 00:00–08:00 跨天错位。
- **与旧版 `repeatRule` 互斥防重**：任务开启「日常任务」时，完成后禁止再触发 `createNextRecurringTaskInTx` / `generateRecurringTask` 复制子任务；UI 上给出清晰提示或互斥联动，避免用户困惑。
- **团队多成员边界**：在团队项目中，仅将归属当前用户的日常任务自动加入其个人「今日任务」，不得误加入无关成员的今日计划；若多人协作同一日常任务，某成员完成今日打卡后的状态同步语义清晰且不引发数据报错。
- **删除与关闭开关**：
  - 手动删除日常任务后，任务从项目与所有今日计划中彻底移除，次日不再出现。
  - 关闭已有日常任务的「日常任务」开关后，该任务变为普通任务，不再在次日自动加入今日。
- **跨午夜在线停留**：应用在本地 00:00 前后持续打开时，跨天后可自动识别新日期并呈现新一日的日常任务待办（无需强制重装或清缓存）。
- **番茄与工时统计**：日常任务每天的焦点会话与工作会话正常落盘并计入每日/每周投入趋势；次日重置仅重置“当日完成态”，不得抹除历史 `focusSessions` / `workSessions`。

## 验收标准
1. **字段配置与标识**：在新建任务弹窗、快捷新增任务弹窗和任务详情页均可开启/关闭「日常任务」；开启后在「我的任务」、「开始工作」及项目任务列表中显示清晰简洁的 `日常` 标识，刷新页面后标记持久保留。
2. **自动加入今日**：将任务设为日常任务后，当天与次日（模拟本地日期切换至明天）打开「我的任务」和「开始工作」页时，该任务均自动出现在「今日任务」中，无需手动添加。
3. **今天完成、明天重来**：
   - 当天点击完成日常任务（含在关闭自动验收的项目中），当天立即显示为「已完成」，运行中的计时会话正常结束，且项目任务列表中**不会**多出克隆副本。
   - 刷新页面后，当天仍保持「已完成」状态，不重复变成未完成。
   - 切换至次日（新的本地日期）后，该日常任务自动再次出现在次日的「今日任务」且处于未完成待办状态，可重新点击开始计时与再次完成，且昨日的历史工作/番茄记录依然保留。
4. **移出 vs 删除**：
   - 当天手动将该日常任务移出今日后，当天不再自动加回；进入次日后，该任务再次自动出现在今日任务中。
   - 手动删除该日常任务后，当天与次日均不再出现。
   - 手动关闭该任务的「日常任务」开关后，次日不再自动加入今日。
5. **既有行为不回归**：普通一次性任务的创建、今日计划增删、人工验收流程、旧版 `repeatRule` 重复任务以及后端关系存储/同步测试全部保持通过。

## 必要技术约束与方案
- 前后端须保持数据契约一致：Go 后端对日常任务的完成接口、持久化读写（含 `business_tasks` 关系与 JSON 负载还原）及多端同步须完整保留新增字段，不丢失数据。
- 日常任务完成时仍兼容前端既有的任务完成返回契约（返回 `"completed"` 状态），以便「开始工作」与「我的任务」既有完成反馈与后续动效无缝衔接。
- 严格遵循项目代码与健康检查规范（TS/TSX 单文件不超 500 行、CSS 不超 1000 行、无未清理临时代码）。

- **浏览器自动化验证（桌面 + 手机视口）**：
  - 覆盖完整用户旅程：在界面创建/切换日常任务并看到 `日常` 标识 → 自动出现在「我的任务」与「开始工作」今日任务 → 当天点击完成显示已完成且刷新保持 → 模拟跨天到明天后自动重新出现在今日待办且可再次完成 → 当天移出今日后明天自动恢复 → 手动删除后彻底不再出现，留存桌面与手机截图证据。
