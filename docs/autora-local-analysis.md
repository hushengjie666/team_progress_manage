# 本机 AI 需求分析

TimeManage 开发环境的「项目 → 任务阶段总览」在可编辑任务的右上角提供 AI 图标。点击打开需求编辑与分析对话弹窗，使用本机 AutoRA 已绑定的目录作为上下文。

此入口仅在 Vite 开发环境启用，生产构建不显示。当前没有云端请求队列、远程设备接入或 Go 后端的 AutoRA 集成接口，不需要数据库迁移。

## 本机配置

1. 启动本机 AutoRA，在其管理页检查登录、模式与权限状态。
2. 将仓库 `.env.autora.example` 中的配置合并到 `.env.local`，填入现有 AutoRA 管理令牌。已有 `.env.local` 应保留原配置。文件仅供本机使用，建议设置权限 `chmod 600 .env.local`。
3. 运行 `npm run dev`，打开 `http://127.0.0.1:1420`。更改配置后重启开发服务。
4. 在 AutoRA 管理页为当前 TimeManage 工作区和项目绑定所需的代码、资料目录，并启用绑定。工作区 ID 与项目 ID 必须与弹窗中提示的 ID 完全一致。其他项目或工作区的绑定不会显示。绑定本仓库时应在 AutoRA 读取范围中排除 `deploy`、`test-results`、`playwright-report` 等生成目录，避免构建或测试产物变化干扰代码扫描。
5. 点击任务卡片 AI 图标，检查目录和读取范围，编辑需求后发送分析请求。

默认管理页为 `http://127.0.0.1:8890/manage`。如果自定义 AutoRA 端口，应修改 `AUTORA_LOCAL_URL` 并使用对应端口打开管理页；弹窗中的管理链接使用默认端口。

令牌只由 Vite 开发服务读取并添加到发往 AutoRA 的请求，禁止使用 `VITE_` 前缀、把令牌写进 URL 或放入浏览器存储。开发桥只允许本机连接、同源网页和明确列出的分析接口；不开放绑定创建、任意文件路径或任意上游地址。AutoRA 地址必须是 `http://127.0.0.1:<port>`。

## 需求与对话行为

- 需求编辑首先保存在弹窗中。点击「保存到任务」才通过 TimeManage 现有任务更新流程保存标题和描述。
- 发送时使用编辑后的需求创建 AutoRA 本地需求快照及专属会话。这是本地分析副本，不代表正式任务已被 AI 修改或确认。
- 需求和目录不变时，追问继续使用同一会话。需求或绑定版本变化后，下次发送创建新快照和会话。
- 对话引用与已发送消息保存在当前浏览器标签页的 `sessionStorage`；关闭并重新打开弹窗可继续查看。切换账号、项目或任务使用各自的引用。任务源版本变化后重新建立讨论。
- 提交使用稳定幂等键。回执丢失时重试原请求，避免再次启动同一轮分析。提交结果不明时保留待重试请求，不允许编辑需求或切换目录。
- 弹窗轮询 AutoRA 持久状态和分析文本。关闭弹窗不会取消分析；重新打开后继续查询。点击「取消分析」后继续以服务端状态判断是否停止。
- 「新建会话」保留 AutoRA 中的历史会话，仅清除当前页面的会话引用。正在执行或结果不明的提交需先处理完毕。
- 分析文本按纯文本显示。代码上下文受 AutoRA 扫描与字节限额约束，界面显示文件数和覆盖限制。

## 验证

```sh
npm run test:autora
npm run verify:fast
npm run verify:e2e
npm run audit:health
```

默认浏览器测试使用模拟 AutoRA 和模拟 TimeManage 后端，覆盖编辑保存、工作区隔离、分析与追问、新快照、幂等重试、恢复、取消、错误和文本展示。

真实本地联调使用运行中的 AutoRA，TimeManage 后端仍用隔离测试数据。请先为 `workspace_e2e` / `project_starter` 绑定本仓库目录，再执行：

```sh
TM_AUTORA_LIVE=1 npm run test:e2e -- tests/e2e/task-ai-analysis.spec.ts --project=chrome
```

真实联调用例要求 AutoRA 为 observe 模式，只创建分析副本、提交排队请求并取消，不启动模型。截图保存在对应 `test-results/` 子目录。

本次本机检查发现 AutoRA 为 observe，Codex 已登录，但返回 `permissions_unsupported` / `validation_pending`。因此能够验证真实连接、目录上下文、需求快照、会话、提交与取消，尚不能验证真实模型分析及真实追问。必须先在 AutoRA 完成只读权限验证并正常启用 analysis，界面才能展示其真实分析结果；本接入没有改变 AutoRA 的运行模式或权限策略。
